## 1. 推荐路线

采用 **Cocos 中设计和验收实际界面，image-2 提供风格探索与独立美术资源，Figma 提供辅助评审** 的路线。

主线：

```text
页面与状态清单 + 视觉简报 + 首包预算
→ 一张风格探索板 + 可量化的组件规范
→ Cocos 游戏主界面灰盒（真实百关几何中的代表关）
→ 一小批独立资源直接导入，做成可交互视觉试样
→ 在引擎预览和手机上校准，确认第一套质量基线
→ 复用同一资源与 Prefab 扩展全页面、全状态
→ 百关适配 + 功能接入 + 真机/包体/性能验收
```

Figma 在风格评审和试样通过后，按需整理组件说明、同源资源和关键截图；**不作为 Cocos 开工的串行前置，也不要求百关逐张转绘**。安全区、资源预算和抖音构建验证从试样开始介入，最后做完整复验。

最小闭环是“一个按钮底板/猫咪资源 → Cocos 实际尺寸和交互 → 截图与触控检查 → 修正源资产或参数”。先证明这条链有效，再增加生产数量。不会把“Cocos 当前能画出来”自动当成“美术质量合格”。

## 2. 对所贴建议的项目化修正

| 建议 | 本项目处理 | 原因/依据 |
|---|---|---|
| 游戏主界面优先、低压力、少入口 | 采纳为推荐方向 | 玩家主要时间在局内；符合 D010 |
| image-2 风格板、独立资源 | 采纳，风格板只供探索；资源单独制作与验收 | 一张拼图不能保证可切片、九宫格或跨状态一致 |
| Figma 轻用 | 进一步移出必经链路 | 若仍等组件板和所有关键页面完成才进引擎，仍会延迟发现问题 |
| 1080×1920 设计分辨率 | 保留 **750×1334 逻辑坐标** | catalog、场景和既定尺寸均基于此；高分辨率素材不等于更换逻辑画布 |
| 底部发射器 | 不采用；保持 `(375,675)` 中央 360° 引路猫窝 | D003；底部只放三道具等 UI |
| 终点猫窝 | 改回单入口“罐头老巢”失败设施 | 三消回窝才是成功，不能暗示猫沿轨道到终点就通关 |
| 红/蓝/黄/绿/紫普通猫、炸弹猫 | 不采用；保留橘猫、布偶、蓝猫、三花、玄猫 | 五种既定品种；彩虹猫属既定道具，无新增炸弹猫 |
| 鱼干/毛线球/猫爪三道具 | 不替换玩法；保留逗猫棒、猫薄荷、彩虹猫 | 鱼干是货币；毛线球/猫爪可作装饰，不能混淆道具语义 |
| 暂不做图鉴/外观，只做十个界面 | 首轮试样可缩小，**首发范围不缩小** | 保留 P00～P11、12 图鉴、轻量外观、奖励/分享及异常流程 |
| 失败只有再试一次 | 补全免费/广告复活、重开、退出与异常状态 | 1～5 关一次免费；6 关起每次有效广告一次复活、单局不限次数 |
| 五列关卡网格 | 作为待评估候选，当前保留十章脚印地图 | 不因通用建议暗改已定导航；UI-02 可比较可读性与滚动成本 |
| 首包放前十关全部资源 | 按加载依赖划分，优先首页与首关必要资源 | 1～10 关若共用资源可自然复用；不为整数关卡范围塞入额外大图 |
| 顶部固定留 80～120px、首页两秒加载 | 固定留白只作草图参考；两秒是优化愿望 | 安全区需动态换算；当前首次可交互目标为常规网络五秒内，需实测 |

“开始回窝”“猫猫到家啦”可进入文案候选；失败原因暂沿用“罐头仓库挤满啦”。首页新用户与回流用户应分别明确开始/继续第 N 关，不能用可爱文案隐藏进度。以上未确认的新导航、文案、色值不覆盖产品规格。

## 3. 各工具负责什么，哪个文件说了算

| 对象 | 生产来源/职责 | 校准方式 |
|---|---|---|
| 玩法与几何 | 有效规格与 `design/track-review/catalog.source.json` | 渲染、碰撞与设施锚点来自同源转换；不手抄另一套路线 |
| 视觉方向 | [01](01_UI_DIRECTION.md) + 获选风格样例 | 所有者评价气氛、层级和猫咪吸引力；Codex 做可读性自检 |
| 美术像素 | 获批的独立源资产与导出资产 | 同一份导出图直接导入 Cocos；Figma 展示相同资产 |
| 尺寸/颜色/字体 | 一份版本化 token 表和已授权字体记录 | 先记录具体数值，实施后由统一配置/Prefab 消费，避免多套手工改值 |
| 布局与状态 | Cocos Prefab、布局参数和视图状态契约 | 引擎中直接调整；Figma 只同步说明或截图 |
| 视觉验收基线 | 所有者确认的 Cocos 代表页面截图及其版本清单 | 后续相同场景/状态/设备条件回归；不随每次代码变化自动替换基线 |
| Figma | 风格/组件说明、关键评审画面与差异批注 | 不重画已经批准的猫、背景、按钮底板；不把 Figma 效果再解释一遍给引擎 |

建议随第一批资产建立轻量 `art/exports/ui_asset_manifest.json`，随首个试样建立 `art/qa/ui-baseline/`。它们尚不存在，不在本轮建空文件或自动同步框架。

基线记录至少包括：源几何哈希、资产 ID/哈希、字体文件/授权、token 版本、Prefab/代码版本、页面状态/关卡/测试数据、视口与安全区、截图、审批与缺陷结果。变更资产就回到资产检查；变更布局就回归相关页面；仅 Figma 漂移不反向覆盖 Cocos。

当 Figma 原生制作一个简单矢量图标确有收益时，可将其确定导出作为该图标唯一源输出并登记；禁止出现同一图标由两种工具分别维护的副本。

## 5. 页面范围和开发顺序

第一条体验链按现有规则规划：`P00 启动 → P01 首页 → P03 准备（首关简化）→ P04 游戏 → P06 胜利 / P07 复活 → 下一关或重试`。是否将准备改为同屏薄层由 UI-02 提案决定，不能直接删除准备能力。

| 页面/状态 | 首轮验证内容 | 全量阶段补齐 |
|---|---|---|
| P04 游戏，最高优先级 | 关卡/目标、呼噜、暂停、中央当前/下一只猫、三道具、入口/老巢 | 所有关卡、两障碍、开中末局、危险与暴走、道具选择/取消 |
| P01 首页 | 一个开始/继续主按钮，猫咪主视觉，低权重次入口 | 关卡/图鉴/外观/设置的最终位置、图鉴解锁提示 |
| P06 胜利 | 星级、小鱼干、下一关 | 重玩、翻倍、分享、奖励重复回调；第 100 关返回地图，无第 101 关 |
| P07 失败/复活 | 原因、免费或视频复活、免费重开、返回 | 免费额度用过、加载、取消、不可用、失败、再次复活、旧回调 |
| P05 暂停 | 继续/重开/设置/返回 | 重开/退出确认、后台恢复，遮罩阻断瞄准 |
| P00/P03/P10/P11 | 最小加载、准备、设置、错误/Toast 容器 | 真实加载/重试、合规入口、首关/常规准备、库存和平台能力降级 |
| P02 地图 | 节点的锁定/当前/通关/三星状态 | 十章 100 关、自动定位当前关、章节加载与重试 |
| P08/P09 | 首轮只盘点所需卡片/外观状态 | 12 图鉴与详情、轻量猫窝/拖尾外观、购买/拥有/使用中 |
| 引导/道具说明/确认 | 复用遮罩和 Dialog 结构 | 首次发射、交换、障碍提示，取消不消耗、空库存说明 |

拟议首页保留“关卡/图鉴/外观”三个业务次入口和独立小设置按钮；录屏分享主要放结算。历史文档对首页录屏/活动入口存在冲突，此布局属于 **Q004 待确认提案**，不表示删除分享，也不因此增加活动系统。

先做 L001 与紧凑 L100；检查 L020/L021 的 64→56px 切换。L100 在源文件中 `threeLayerDegrees=108`、`maxLayers=3`，适合暴露密集层问题；这只是静态几何选样依据，不是“最难关”或可通关结论。最终仍检查全部 100 关。

## 6. 首轮美术与风格板怎么做

风格简报建议：**温暖奶油底、圆润软糖猫、轻微立体、少量毛绒暗示、清楚的深色文字**。猫咪可以有材质，按钮和 HUD 保持干净；避免细碎毛发、厚木框、满屏挂件或强烈高光。具体色值和造型在 UI-03 验证，不在这里假装已定稿。

一张探索板包含五猫缩略、主/次按钮底板、弹窗底板、呼噜槽、暂停/返回/视频等图标方向、少量猫窝/爪印元素、局部背景材质。移除通用提示词中的金币系统和额外道具；小鱼干、星级、三道具使用本项目语义。

把两份产物分清楚：

- **风格探索图**：评审材质、光向、色彩和气氛，标注“概念参考，不可直接切片交付”。不依赖模型生成的伪字、假标注和尺寸。
- **组件规范表**：Codex 明确字号、间距、圆角、资产锚点、九宫格 inset、状态、热区、文字溢出规则、动效时长；数值以引擎试样校准。

首批生产建议为五猫各一张静态清晰源图、一个中性局内背景、入口/中央窝/单洞老巢、两种按钮底板、一个弹窗底板、一套最小语义图标和三个道具图标。先验证五猫实际尺寸，再扩展六类表情/动画状态；首轮静态资源通过不等于角色资产全部完成。

独立资产提示必须说明用途、正面/统一视角、同一光向、无文字、透明背景（适用时）、完整轮廓、足够透明留边，并带获选参考。透明要求不能代替实际 alpha 检查。禁止从整屏画面裁出被文字/猫链遮挡的“按钮”。

image-2 适合角色、设施、插画、纹理与有辨识度的美术底板。暂停/关闭等简单符号和规则圆角形状可以确定性制作；无需为了工具流程把每个 UI 元素都交给生图。实际可用生成工具若不暴露模型选择，应如实记录，不能宣称已调用指定模型；不新增付费 API。

## 7. 资源交付契约与目录

沿用已有 `assets/game/`，不平移成建议中的另一套根目录，也不重建 Cocos 工程。以下为按需创建的候选目录，现有重复资源及 `.meta` 在确认引用前原样保留。

```text
art/source/                         获选独立源图/字体授权记录
art/exports/                        可导入资产、资产清单
art/qa/ui-baseline/                 获批截图、设备与版本记录
assets/game/art/{cats,facilities,backgrounds,ui}/
assets/game/fonts/
assets/game/prefabs/{ui,gameplay}/
assets/game/scripts/ui/             页面与共用视图
assets/game/scripts/gameplay/       几何/猫链/设施表现
```

| 类型 | 生产交付 | 进入 Cocos 后检查 |
|---|---|---|
| 按钮/弹窗 | 无字底板；四边 inset、最小/最大显示尺寸 | Sliced 九宫格，角不拉坏、装饰独立、按下不跳版 |
| 文字/数字 | 文案与字体文件/授权、字号/行高/对齐/溢出规则 | Label 为默认；BitmapFont 仅在实际性能/清晰度需求成立时选用 |
| 图标/五猫/设施 | 透明 PNG 源、统一留边/锚点、语义 ID | 黑白底边缘；56/64px 及 48px 压力检查；设施洞口与切线对齐 |
| 背景 | 无猫链/轨道/UI 的独立图，标注可裁边 | 可延展/裁边，不裁掉交互和玩法；不机械上 4K |
| 轨道 | 源几何生成的路径与可复用材质 | 与碰撞同源；不能把复杂曲线当九宫格任意拉伸 |
| 光效 | 独立透明图或少量引擎特效 | 不吞没猫花纹、不挡射击窗口、不造成持续大面积透明叠加 |

Cocos 3.8 的 Sprite 提供 Sliced、Tiled、Filled 等模式；九宫格用于可伸缩底板，进度填充可用 Filled。具体取舍在试样验证。[Cocos Sprite 文档](https://docs.cocos.com/creator/3.8/manual/zh/ui-system/components/editor/sprite.html)

每项资产除 [04](04_ASSET_GUIDE.md) 的字段外，增加：导出倍率、设计显示尺寸、内容边界、九宫格 inset、压缩参数、哈希、目标 Bundle、实际 Prefab 引用、版本与通过状态。同一导出资产分发到 Figma/Cocos 时保留身份，不经过 Figma 截图或重复有损导出。

## 8. Cocos 试样与 Prefab 计划

当前只有 `main.scene`、GameRoot 运行时 Graphics/Label 绘制和 24 关配置，**没有 Prefab**。灰盒试样先建立有限的视图验证入口，读取百关源派生的代表关快照；由此验证几何/布局，不借机实现全量规则。试样数据需清楚标记，不能让演示复活按钮冒充真正复活。

建议按实际页面提取组件，先少量复用，再扩展；不预先搭一个通用 UI 框架。

| 顺序 | 候选组件 | 输入/输出职责 |
|---|---|---|
| 1 | `CommonButton`、`IconButton`、`DialogBase` | 状态、文本、图标、热区；发出单次点击/关闭意图 |
| 2 | `CatView`、`LauncherView`、`SourceView`、`LairView` | 读取快照/几何表现；不修改猫链、发奖或判胜负 |
| 3 | `HudPanel`、`BoosterItem`、`PurrBar` | 关卡/进度/库存/暴走；发出暂停/道具意图 |
| 4 | `HomeView`、`WinPopup`、`RevivePopup`、`PausePopup` | 导航与视图状态；复用底板和按钮 |

沿用 [03](03_COCOS_STRUCTURE.md) 的单场景建议：Background、Gameplay、HUD、Page、Modal、Toast。引导可作为独立 Guide 层，位于玩法/HUD 之上、Modal 之下；打开弹窗时隐藏或阻断引导热区。UI 热区和弹窗优先消费输入，释放手指不能穿透成一次发射。

布局基准仍为 750×1334。轨道/猫链/发射器/设施使用同一个等比变换，设计坐标到 Cocos 坐标只在边界转换一次；触摸反向映射使用同一变换。UI 锚定安全区域，背景可单独铺满。若安全区导致冲突，先调整 HUD/装饰与外围留白，检查整体适配，不单独挪发射器或改控制点。

## 9. Figma 的最小用途

只在既有 `mini-game` 文件 `83pqrCcig644vC20QXM5G1`、节点 `11:7101` 对应本项目 V2 区域内工作；不新建“喵喵回窝_UI”文件，不建 V3，不使用付费能力。本轮未连接或修改 Figma。

需要使用时，在该区域按三组整理：

1. **风格与组件说明**：已选色板、字体、同源按钮/面板/图标、状态说明与锚点。
2. **关键画面评审**：游戏主界面、首页、胜利、复活、地图；优先放 Cocos 实际截图供批注。暂停沿用组件规范，不为数量补全页面精稿。
3. **资产索引**：资产 ID、仓库路径、导出版本、inset、尺寸和批准状态；不是第二个主导出仓库。

截图评审板应明确标为“引擎截图/参考”，不能声称可编辑 UI 已完成。只有要比较导航或布局方案时才搭必要的可编辑示意，且不要求逐像素还原 image-2 图片。缺少 Figma 板不会阻塞已授权的 Cocos 试样。

## 10. 如何证明新路线降低了损耗

代表场景使用固定关卡、固定状态数据、固定字体/资产版本和固定视口截图。先看原始像素尺寸，再看手机真实显示；漂亮的大图缩略不能替代判断。

| 检查项 | 首个试样的通过条件 |
|---|---|
| 资产直接复用 | 清单能追溯到源图与同一导出资产；无手绘近似替代，无整屏贴图盖热区 |
| 层级与触控 | 三秒内识别当前猫、下一只、轨道、失败终点和主按钮；无遮挡/热区冲突/输入穿透 |
| 五猫与障碍 | 五猫在 64/56px 下可由花纹轮廓区分；48px 压力检查；后续两障碍不同状态可读 |
| 底板与字体 | 九宫格拉伸不变形；短/长按钮文案、关卡 1/100、变化数字、禁用/加载都不裁切 |
| 多尺寸 | 基准、窄屏、长屏，加刘海/胶囊/底部手势场景；记录实际设备及系统/宿主版本 |
| 交互状态 | 暂停/继续、交换、道具取消、遮罩、胜败切换；演示状态与真实规则验证分别记录 |
| 情绪与美术 | 所有者认可猫咪、质感与画面；通过自检不等于自动取得审美批准 |

第一套基线形成前：引擎试样对照已选风格、资产和数字规范检查，保留差异记录。基线形成后：新截图对照**已批准的引擎截图**，动态特效与文本抗锯齿单独分析，不用一个像素相似分数混代布局/美术/交互。

发现问题按来源修：资产脏边修源图；九宫格变形修 inset 或底板；文字溢出修字体/排版；层级不清修 UI/背景；几何错位修同源转换。所有者未认可的“降级还原”不能靠更新基线掩盖。

## 11. 包体、分包与发布验证

阶段 1 就列预算，阶段 4 首次构建测量，阶段 7 完整验收。主包包括引擎/代码/字体/音频等成本，不能把 4MB 全当 UI 图片额度。

| 加载组 | 推荐内容 |
|---|---|
| 启动必须 | 加载反馈、首页、首关所需背景/轨道材质、五猫最低必要状态、通用按钮/弹窗/必要字体音频 |
| 局内常用 | 共用猫/设施/道具/反馈，按真实引用保留或加载；共享即可覆盖多个关卡 |
| 按需内容 | 后续章节大背景、图鉴大图、非默认外观；进入前预取，失败可重试，不无限加载 |

优先用现有引擎支持的 Asset Bundle 分包，按页面/章节实际生命周期配置；CDN 是有额外运维需求时才评估的选项。Cocos 可将按文件夹配置的 Bundle 构建为小游戏分包，运行时需主动加载，单建目录不会自动完成分包。[Cocos 小游戏分包](https://docs.cocos.com/creator/3.8/manual/zh/editor/publish/subpackage.html)

截至本次核验，抖音代码包文档对普通分包游戏列出的默认限制为总包 20MB、主包 4MB、单个分包 20MB；本项目无虚拟支付，不套用扩容例外。继续采用主包小于 4MB 的项目预算并留余量，发布时以目标 IDE/平台实际校验为准。[抖音代码包说明](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/guide/basic-function/subpackages/introduction)

保留 PNG 无损源；WebP/其他压缩格式先验证 Cocos 导入、透明边缘、目标抖音构建与手机解码，再决定输出。小图按共同生命周期合图集，大背景不混入常驻 UI 图集；检查跨 Bundle 依赖导致的重复打包。压缩文件大小、解码后内存、帧率、冷/热启动分别测量。

不要提前承诺两秒加载；沿用现行常规网络首次可交互五秒目标，并记录机型、网络条件、冷/热缓存及多次样本。2 秒可作为后续优化目标，不能替代实测或偷改规格。

Cocos 3.8 的抖音构建生成包含 `game.json`、`project.config.json` 的发布目录；在开发者工具和实际手机上验证该构建，浏览器预览只是早期检查。[Cocos 发布到抖音小游戏](https://docs.cocos.com/creator/3.8/manual/zh/editor/publish/publish-bytedance-mini-game.html)
