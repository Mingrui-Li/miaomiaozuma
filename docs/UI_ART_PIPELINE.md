## 2. 强制流程

每个核心界面、重要弹窗、猫咪角色组和关键玩法画面必须依次经过：

> ImageGen 概念图 → 视觉确认 → Figma 可编辑设计 → Figma 评审 → Cocos 实现 → 真机截图对照

禁止跳过 Figma，禁止从文字需求直接制作正式 Cocos UI。

100 关中的每一关都必须有对应 ImageGen 视觉母版和 Figma 可编辑关卡稿；可以共享组件与背景主题，但不能只设计第 1 关后让其余 99 关由开发自行猜测。

项目所有者使用 ChatGPT Plus，并指定图片生成阶段优先使用 `gpt-image-2`。如果当前图片生成工具允许选择模型，必须选择 `gpt-image-2`；如果产品界面只提供统一 ImageGen 能力而不暴露模型选择，应使用该环境提供的最新模型，并记录实际情况。不要因为账号类型自行假设存在独立 OpenAI API 额度，也不要为了生成设计稿额外接入付费 API，除非项目所有者明确授权。

## 3. ImageGen 概念图

生成前先准备视觉 Brief：

- 画面目标和玩家当下情绪
- 屏幕比例与安全区域
- 必须出现的信息和按钮
- 视觉焦点
- 猫咪品种和动作
- 禁止元素
- 参考关键词：软糖质感、粗轮廓、暖色、干净、高对比、轻微立体、萌而不幼稚

每个核心画面先产出 2～4 个明显不同的方向，选择一个方向继续精修。不得同时混用多个方向的画风。

ImageGen 概念图用于确定构图、配色、气氛、视觉层级、角色姿势和反馈强度。概念图不是可直接开发的最终 UI，也不能替代交互状态设计。

## 4. Figma 重建

Figma 必须把确认后的概念图重建为真正可开发的界面：

- 使用独立、可编辑图层。
- 建立颜色、字号、圆角、阴影、间距等设计变量。
- 按钮、货币栏、弹窗、卡片、进度条建立组件和状态。
- 使用 Auto Layout 或等价约束处理不同屏幕尺寸。
- 标注安全区、点击热区、动效意图和资源切图方式。
- 为正常、按下、禁用、选中、加载、失败和空状态提供设计。
- 不得把整张概念图导入并覆盖透明点击区作为最终稿。

目标节点下必须完成：

1. 启动/加载页
2. 主界面
3. 第一关完整游戏画面
4. 暂停弹窗
5. 胜利结算
6. 失败与复活
7. 关卡地图
8. 猫咪图鉴
9. 道具选择
10. 录屏分享引导
11. 100 关独立路径的黑白逻辑验收板（含相似度、实际首撞、断口与末段救场证据）
12. 100 关逐关游戏画面与参数标注

Figma 只在现有 V2 分区上修正，不新建 V3 分区。所有关卡稿必须逐张叠加对照其 ImageGen 母版，并单独记录位置、字号、中心线、入口、方向、老巢和发射器检查结果。

## 5. Cocos 实现

- 只使用已确认的 Figma 尺寸、组件、颜色和资源。
- 先实现响应式布局和交互状态，再补动效。
- 不得用近似颜色、默认字体或临时图标替代设计稿并宣布完成。
- 猫咪与高频特效使用图集和对象池。
- UI 逻辑与平台能力解耦，广告或分享不可用时界面仍要正常反馈。
- 重要动效要有明确时长、缓动和中断规则。

## 6. 视觉验收

- 3 秒内能否看懂当前最重要的按钮或目标。
- 猫咪是否比货币、装饰和次要按钮更吸引视线。
- 文字在浅色、深色和复杂背景上是否都清晰。
- 五种猫缩小后是否仍能仅凭花纹和轮廓区分。
- 常用按钮是否适合单手拇指触达，点击热区是否足够。
- 刘海、圆角、底部手势条和抖音胶囊区域是否避让。
- 弹窗是否有明确主次按钮和可退出方式。
- 动画是否增强反馈，而不是拖慢下一次操作。
- 游戏进行时是否仍能看清轨道、当前猫、下一只猫和终点危险程度。
- 是否存在模糊、拉伸、锯齿、风格混杂或 AI 生成残缺细节。

## 7. 真机对照

Cocos 实现后至少保存：Figma 目标画面、常规全面屏截图、窄屏截图、带刘海或胶囊安全区截图。

逐项比较布局、间距、字号、颜色、圆角、阴影、资源清晰度和视觉焦点。明显偏差必须修正，不能以“不同引擎效果不同”为理由跳过。

## 8. 可接受的例外

核心算法灰盒允许在 ImageGen 和 Figma 之前开发，但只能使用占位圆形、简单轨道和调试文字，目的仅限验证轨道移动、发射插入、匹配、回吸、连锁和性能。

灰盒不得进入正式发布包，也不得作为最终 UI 的基础直接堆叠美术。进入正式视觉实现前仍须完整走完本工作流。
