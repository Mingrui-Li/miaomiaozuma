# 01 · UI 方向与质量约束

更新：2026-09-09。**UI-03 风格候选与基础规范已交付，视觉样式未冻结。** 阶段见 [08](08_UI_DEVELOPMENT_ROADMAP.md)，页面/状态见 [09](09_UI_STRUCTURE_AND_STATES.md)，候选图、令牌/字体/状态与自检见 [10](10_UI_STYLE_GUIDE.md)。

## 方向与生产策略

小、简单、可爱、解压、猫咪主题、低压力。优先清楚、亲切、轻盈，有适当留白；猫和操作目标最突出，背景退后。可探索圆润轮廓、少量柔软高光、轻微果冻反馈，不继续默认继承满屏花园、厚木框和高密度装饰。

用户已否定“整张 ImageGen 图 → Figma 还原 → Cocos 再还原”的强制路径，原因是两次转绘造成明显损耗。**停止旧批量生图与还原任务；不自动启动任何替代流程。**

后续规划路线（D012 承接 UI-01）：页面/状态清单 → 风格探索与量化规范 → Cocos 代表关灰盒 → 小批独立资产直入 Cocos → 引擎/手机校准 → 全页面/百关扩展与验收。Figma 为辅助评审，不作为 Cocos 前置；首轮先证明按钮、五猫、面板能直接复用，再扩展素材数量。D013 已授权并完成风格候选制作，未开始独立生产资产或引擎改造。

当前候选为奶油底、短绒五猫、暖橘主按钮和浅面板，见 `art/concepts/ui03/style_board_02.png`；精确数值在 `design/ui/ui03.tokens.json`，全部标 candidate。深棕按钮字、较深绿细呼噜条与可读禁用文字已做色对计算。五猫完成64/56/48框的彩色/灰阶概念预检；玄猫口鼻和绒毛留边需在独立资产中改善，详见 UI-Q01/02。图片不直接充当透明图集。

image-2 风格板只决定气氛与材质，不当作可切片生产图集。视觉资产/字体/token/Prefab 与批准的引擎截图组成可追溯基线；新截图不能自动覆盖批准版本。所有者确认方向与首个引擎视觉样本，Codex 完成每批自检与差异记录。完整职责、依赖和进入条件见 [08](08_UI_DEVELOPMENT_ROADMAP.md)，本轮没有实施试样。

## 基础视觉建议（待样例验证）

- UI-03 给出奶油背景 `#FFF5E6`、面板 `#FFFBF4`、深棕字 `#4A332B`、主橘 `#FFC078` 的候选值；完整色对见10。数值未冻结，不从概念图取色替代令牌。
- 字体先列 Noto Sans CJK SC 为正文/HUD候选，霞鹜文楷为大标题对比候选；官方来源与许可证已查，具体文件未导入/验缺字，选择未定。图片文字不能当最终文本。
- 保留 750×1334 逻辑基准，不照搬外部建议的 1080×1920；高分辨率源图与逻辑画布分别管理。旧间距 8/16/24/32/48、标题 36～48、按钮 32～34、正文 28 可作试排起点，不是新视觉验收结果。
- 热区以设计基准 88×88 为起点，按设备与安全区校准；可见图标可小于热区，但热区不能互相抢输入。

## 按钮

- 每页/弹窗只有一个最强主操作；文字简短、优先动词，水平垂直居中；带图标时整个“图标+文字”组居中。
- 圆角、稳定边框、轻微按压体现层级，避免大量渐变/发光掩盖状态。
- 正常、按下、禁用、加载齐全；道具增加选中/库存为零；广告增加不可用/取消或失败后恢复。
- 禁用仍可读且说明原因；加载防重复提交、不挤动布局。
- 广告标明视频与奖励，不伪装免费；保留免费重开和返回，不显示“本局复活次数已用尽”。

## 弹窗与反馈

- 统一底板、标题、内容、操作区；标题居中，数字按行对齐，内边距和行高一致，长文本不溢出。
- 暖色弱遮罩，背景可辨但不接受玩法输入；重开/离开确认与继续游戏明确区分。
- 胜利突出猫、星级、奖励、下一关；翻倍/分享次级；第 100 关不出现第 101 关。
- 失败用“罐头仓库挤满啦”等温和表达，准确说明复活效果，不责怪玩家。
- 错误、无广告、弱网、加载失败、奖励到账均有恢复动作；Toast 不长时间遮挡发射猫或猫链。

## HUD 与玩法画面

- 层级：当前/下一只猫与瞄准 → 猫链和轨道 → 老巢提示 → 呼噜进度 → 道具与次要数值。
- 暂停、关卡、目标/呼噜信息克制排布，不塞满货币和活动入口。
- 轨道和碰撞共用几何源；设施洞口位置/朝向与端点一致。不能为构图移动发射器或拉伸轨道。
- 发射器基准 `(375,675)`，下一只猫不能压近层轨道；三道具在底部可触区；UI 事件优先于瞄准。
- 顶部 88px、底部从 1260 起先作背景留白，最终采用真实安全区与胶囊避让；09 试排把 HUD 收在 `88..176`、三道具放在 `1172..1260`。现有设施示意仅余约 12/10px，仍需灰盒验证，不能视为百关适配通过。
- 下一只预览按每关静态预检选择有限右下候选位置。L087 最差占位间隔约 6.60px，列为 UI-R01；不移动发射器或轨道解决。
- 危险反馈局限末段，温和脉冲而非满屏红闪；低压力不删除失败终点或后期挑战。

## 图标与猫咪元素

- 统一视角、光向、描边和底座，语义优先。图鉴用卡片/猫档案，外观用猫窝/装扮，不用奖杯或首页房屋代替。
- 暂停、返回、关闭、设置等使用易懂符号；不依赖 Emoji 或系统字形充当正式素材。
- 五猫在真实 64px / 56px 检查，另做 48px 压力检查；玄猫五官不能淹没在深色里。颜色之外保留花纹与轮廓。
- 状态含移动、挤压、贴贴、回窝、紧张、庆祝；不把装饰猫误当第六种匹配品种。
- 猫耳/爪印只在重点使用，不给所有按钮堆耳朵、尾巴和挂件。

## 禁用事项

- 旧稿换色冒充从零设计；擅自续跑旧 129 项生图队列。
- 整张含文字、按钮、猫链的截图盖透明热区当正式 UI；转绘损耗用“差不多”验收。
- 装饰过密、伪立体厚框、风格混杂、模糊拉伸、乱码、未授权字体、系统默认控件直接交付。
- 改几何迁就美术、猫离轨、双入口老巢、底部发射器、闭环或断头轨道。
- 自动广告、虚假奖励、难找的取消入口、伤害猫咪表达、频闪、动效长时间锁操作。

## 自检与交付

每页/组件须有：来源与状态、尺寸锚点、文本规则、热区、交互状态、资源清单、截图和缺陷记录。检查常规/窄屏/长屏及刘海胶囊安全区；无论用什么工具，都要验文字居中、无遮挡和触控。

先以第一关和紧凑后期关验证游戏主界面，再做首页、胜利/失败和暂停；增加 L020/L021 尺寸边界、L022/L024 上下设施、L087 下一只预览检查。随后覆盖 P00～P11 和百关。每关都要检查适配；共享主题资源配合百关同源几何，不要求 100 张独立背景或逐关 Figma 转绘。制作按后续明确任务执行。
