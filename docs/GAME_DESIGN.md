> 产品阶段：抖音小游戏首发版  
> 本文保留详细产品规格；最新决策与适用优先级见 [项目决策日志](05_DECISION_LOG.md) 和 [AGENTS](../AGENTS.md)。

## 1. 产品定义

| 项目 | 定义 |
|---|---|
| 正式名称 | 喵喵回窝 |
| 类型 | 轨道插入式三消 |
| 平台 | 抖音小游戏 |
| 画面 | 竖屏 2D |
| 操作 | 单指瞄准，松开发射；点击发射器交换当前猫与下一只猫 |
| 单局时长 | 60～120 秒 |
| 核心用户 | 喜欢猫、萌系内容、轻度消除和解压反馈的用户 |
| 情绪价值 | 可爱、贴贴、收集、连锁消除、逆转清屏 |
| 核心承诺 | 每 10 秒左右获得一次明确正反馈，每局至少一次“呼噜暴走”机会 |

一句话介绍：五种猫从唯一迷路入口沿连续轨道走向罐头老巢；玩家操作场地中央的 360° 引路猫窝，将同品种猫凑成三只以上，让它们贴贴回窝并阻止链头进入老巢。

## 2. 设计原则

1. 首局先展示魅力，再教学规则。第一关必须出现五种基础猫和一次保底“呼噜暴走”。
2. 规则熟悉，反馈新鲜。玩家可以立即理解三消，但必须记住“贴贴回窝”和“呼噜暴走”。
3. 不表现伤害猫咪。匹配结果统一是猫咪开心回窝，而非爆炸或死亡。
4. 一人可完成。新系统必须证明能明显提升留存、传播或收入，否则不进入 MVP。
5. 先做手感，再做内容。轨道插入、断层回吸和连锁不稳定时，禁止批量制作关卡。
6. 好看是功能要求。正式 UI 必须遵守 `UI_ART_PIPELINE.md`。

## 3. 核心玩法

### 3.1 基础规则

每关只有一个迷路入口、一条连续开放轨道、一个中央引路猫窝和一个罐头老巢。猫咪只从迷路入口生成，并沿轨道的唯一方向向老巢前进；玩家从场地正中央的引路猫窝向四面八方发射一只猫并将它插入队伍：

1. 三只或更多同品种猫连续相邻，触发“贴贴”。
2. 贴贴成功的猫跳进纸箱，离开队伍并得分。
3. 队伍出现断层后重新吸合；若再次形成三连，触发连锁。
4. 入口队列耗尽、入口关闭且场上全部猫咪清空后才胜利。
5. 任意链段的链头进入罐头老巢失败阈值后立即失败。
6. 玩家可以点击发射猫窝，交换当前猫和下一只猫。

入口、轨道、发射器、老巢的拓扑、状态机、插入、回吸和胜负判定以 [`CORE_GAMEPLAY_SPEC.md`](CORE_GAMEPLAY_SPEC.md) 为唯一实现依据。

### 3.2 五种基础猫

五种猫从第一关开始全部出现。它们必须同时依靠主色、花纹、脸型和耳朵轮廓识别。

| 品种 | 主色 | 视觉特征 | 性格表现 |
|---|---|---|---|
| 橘猫 | 橙色 | 额头条纹、圆脸 | 贪吃、开心 |
| 布偶 | 白蓝 | 深色耳朵、大尾巴 | 优雅、慢半拍 |
| 蓝猫 | 蓝灰 | 小耳朵、胖脸 | 淡定、呆萌 |
| 三花 | 黄白黑 | 三色斑块 | 活泼、好奇 |
| 玄猫 | 黑紫 | 尖耳、月牙眼 | 神秘、机灵 |

### 3.3 呼噜暴走

呼噜暴走是首发版本的核心差异化机制：

- 普通消除、额外数量和连锁都会增加呼噜值。
- 呼噜槽满后自动触发，避免玩家因不知道按钮作用而错过首局爽点。
- 画面停顿约 0.3 秒，手机轻震，所有猫咪一起呼噜。
- 随后进入 4 秒暴走：猫链速度降至 55%，每次有效消除额外将链头向入口方向推回 1.5 只猫距离。
- 暴走强化玩家的瞄准和连锁机会，不直接无条件清除一个品种。
- 分数、粒子、飘字、音效和倍率同时升级。

候选表现文案：呼噜暴走、猫步慢下来、连锁好机会、喵得漂亮。

### 3.4 消除反馈

每次普通消除至少包含：

- 猫咪先挤扁再弹起。
- 相邻同类猫出现爱心或蹭脸动作。
- 猫咪沿弧线飞进纸箱。
- 弹射、喵叫、呼噜三层短音效。
- 轻微震动、粒子和分数飘字。
- 连锁时逐级提高动画节奏、音高和文字倍率。
- 六连以上展示“大贴贴”“猫山猫海”等大字。

## 4. 首发关卡

首发固定 100 关、十个章节。五种猫始终全部可见，难度通过序列、速度、轨道、队伍长度和障碍控制，不通过减少猫咪品种来教学。废止“20 模板各连续复用 5 关”的旧方案：每关独立编排路径参数、射击选择、遮挡/接缝、末端救场与生成计划；仅换色、镜像、调速不能作为逐关设计完成证据。各关共享曲线、碰撞与队列实现，不编写特殊关卡代码。前十关候选和整改门禁见 [V2 轨道整改](TRACK_REDESIGN_REVIEW.md)。

### 4.1 第一关：五猫迎宾

目标：在第一分钟同时建立“好看、好懂、很爽”三个印象。

- 五种基础猫全部在开场队伍中出现。
- 无障碍；唯一迷路入口、连续开放轨道与唯一老巢必须在首屏清楚可见。
- 中央发射器四个象限都有可射窗口，第一局就体现 360° 选点，而不是只能攻击第一排。
- 前 20 秒不会失败，终点前保留足够安全距离。
- 前六次发射使用固定的友好序列，保证玩家即使瞄得不完美也容易形成三连。
- 第一次可匹配位置用两只正在蹭脸的同类猫给出非文字提示。
- 第一次发射后才显示一句操作提示；不使用多页教程。
- 呼噜值使用新手倍率，在约 25～35 秒内必定充满。
- 第一次呼噜暴走固定持续 4 秒，并确保玩家至少获得三次清晰可用的瞄准机会。
- 通关目标时长为 45～70 秒，首次通关率目标不低于 85%。

### 4.2 第二关：交换猫咪

- 五种猫全部出现。
- 保持慢速，轨道稍长。
- 教学点击发射器交换当前猫和下一只猫。
- 安排两次可以由断层吸合产生的连锁。
- 呼噜暴走仍有充能保底，但不再提供额外的新手减速。

### 4.3 第三关：第一次完整挑战

- 五种猫全部出现。
- 取消固定发射序列，启用强帮助型随机序列。
- 引入一至三星结算，但仍不加入障碍。
- 让玩家首次体验接近终点后通过连锁逆转。
- 通关后解锁图鉴入口和第一张猫咪卡片。

### 4.4 后续章节

| 关卡 | 章节 | 内容与目的 |
|---|---|---|
| 1～10 | 晴日庭院 | 无障碍；学会方向、插入、交换、回吸与连锁 |
| 11～20 | 纸箱小巷 | 引入纸箱猫，建立目标优先级 |
| 21～30 | 灰尘花房 | 引入灰扑扑猫，训练识别与留后手 |
| 31～40 | 弯桥午后 | 强化远近轨道切换与穿缝射击 |
| 41～50 | 海风猫站 | 引入分段速度，训练暴走时机 |
| 51～60 | 果园仓库 | 组合两类障碍，但不增加新规则 |
| 61～70 | 雪夜长廊 | 管理长链和多个断口 |
| 71～80 | 星光屋顶 | 缩短老巢缓冲，强化近端救场 |
| 81～90 | 灯会巡游 | 全机制组合与高阶连锁目标 |
| 91～100 | 百猫回窝 | 不加新机制，用终章验证完整掌握度 |

### 4.5 障碍

- 纸箱猫：不能直接匹配，左右相邻区域累计发生两次消除后打开并露出猫咪。
- 灰扑扑猫：品种暂时被灰尘遮住，相邻发生一次消除后显露原本品种。

### 4.6 难度与保底

2026-09-07 项目所有者确认：百关按策略复杂度逐步提升，不按轨道长度排序冒充难度。前 20 关保持原几何尺寸；21～100 关使用 56px 猫径、约 72px 轨宽、至少 88px 非相邻轨道中心线间距，重做双层嵌套、局部三层和末端救场结构。旧百关几何图只作被否决的候选，不作为冻结版本。细则见 [难度与无限广告复活](DIFFICULTY_AND_REVIVE_SPEC.md)。

可调参数仅包括：移动速度、初始队伍长度、总生成数、轨道长度、障碍比例、发射序列帮助度和呼噜充能速度。

连续失败两次后启用隐形辅助：

- 移动速度降低 10%。
- 提高下一只猫能在当前队伍中形成有效组合的概率。
- 不向玩家展示“难度降低”等挫败性提示。

## 5. 局外成长

- 通关获得“小鱼干”。
- 根据分数和终点剩余距离获得一至三星。
- 小鱼干只用于解锁猫咪表情、猫窝外观和发射拖尾。
- 首发包含 12 张图鉴卡片，每张卡片由一张插画、一段猫咪吐槽和一个轻量入场动画组成。
- 外观没有数值加成。
- 首发不做体力系统。

主界面固定入口（D019，2026-09-11）：大开始/继续按钮、关卡地图、猫咪图鉴、外观、小设置。录屏分享放在结算，不保留首页独立录屏入口；保留录屏和分享能力，不新增活动系统。

## 6. 道具

首发只提供三个道具：

- 逗猫棒：移除指定的一只猫。
- 猫薄荷：清除目标附近五只猫。
- 彩虹猫：可以与任意品种组成三连。

道具来自关卡奖励、每日首次进入或激励广告。不得增加道具升级、合成或额外货币。

## 7. 商业化

第一阶段广告变现，不做内购。

激励广告位置：

1. 失败复活：队伍后退 25%，并移除最靠近终点的三只猫。
2. 通关翻倍：本局小鱼干翻倍。
3. 开局补给：领取一个指定道具。

约束：

- 前五关不主动展示广告入口，除非玩家主动进入道具补给页。
- 第 1～5 关保留一次免费复活，不调用广告。第 6 关起，玩家每完成一次激励广告即可复活一次，单局广告复活次数不限；不得因为已经复活过而隐藏入口或结束本局。
- 每次广告复活是独立事务：同一次广告完成回调只兑现一次，但新的有效广告完成可以再次兑现。取消、失败、无填充不发奖，免费重开与返回始终保留。
- 没有广告填充时必须明确提示，不能让按钮无响应。
- 只有平台确认完整观看后才发放承诺奖励。
- 主游戏画面不放 Banner。
- 插屏广告不作为首发收入核心，等留存稳定后再测试。

## 8. 录屏与传播

- 从第一版接入自动录屏，每局保留最后约 20～25 秒。
- 高光事件包括：呼噜暴走、八连以上、终点前翻盘、最后一发通关、稀有图鉴解锁。
- 结算页必须有明确但可关闭的分享入口。
- 同一段录屏的分享奖励只能领取一次，并且仅在成功回调后发放。
- 分享画面重点表现猫咪数量、连锁倍率、回窝动画和一句可读标题。

## 9. UI 与美术

当前 UI 目标：小、简单、可爱、解压、猫咪主题、低压力。旧软糖质感、粗轮廓、暖色等仅作为可探索手段，不默认继承旧密集花园构图；具体视觉方案见 [UI 方向](01_UI_DIRECTION.md)，尚待小样确认。

每只基础猫需要六个状态：正常移动、被挤压、开心贴贴、飞入猫窝、紧张、胜利庆祝。

旧 ImageGen → Figma → Cocos 强制顺序已因转绘损耗停止采用。新的工具职责、唯一视觉基线与验收路径须单独确认；现有 `UI_ART_PIPELINE.md` 保留为历史记录。美观、可读、几何一致、多尺寸与真机 QA 仍是要求，未被取消。

## 10. 技术约束

- Cocos Creator 3.8.7 或更高兼容版本，TypeScript，2D SpriteAtlas。
- 使用单场景加 UI 面板，避免不必要的场景切换。
- 贝塞尔轨道预采样为坐标点；每只猫保存轨道距离，不使用真实物理系统模拟队伍。
- 发射碰撞后计算数组插入点；消除后重新计算目标距离并补间回吸；吸合结束再次检测匹配。
- 猫咪、粒子、弹射物和飘字使用对象池。
- 关卡完全数据驱动。
- 广告、录屏、分享、存档、震动和数据上报通过平台适配层隔离。
- 主包目标不超过 4MB，其余美术按用途或章节分包。

建议模块：`PathSystem`、`CatChain`、`Shooter`、`MatchResolver`、`PurrSystem`、`LevelConfig`、`FeedbackSystem`、`SaveSystem`、`PlatformAdapter`、`Analytics`。

## 11. 数据事件与目标

核心事件：启动、教学步骤、关卡开始、关卡胜利、失败、退出、呼噜暴走、复活展示、广告完成、分享点击、分享成功、图鉴解锁。

关卡结算附带：关卡号、尝试次数、耗时、发射次数、最大连锁、暴走次数、失败位置、是否使用道具、是否复活、复活次数、广告尝试/完成次数、各次复活后存活时长与最终是否通关。游戏内活动耗时与广告观看耗时分开记录。

初期调优目标：

| 指标 | 目标 |
|---|---:|
| 第一关完成率 | ≥85% |
| 第三关到达率 | ≥65% |
| 首次会话时长 | 6～10 分钟 |
| 次日留存 | ≥20%，争取 25% |
| 七日留存 | ≥7% |
| 人均单局数 | ≥5 局 |
| 激励广告主动观看率 | ≥15% |
| 录屏分享点击率 | ≥5% |

这些是调优目标，不是收入或流量承诺。

## 12. 开发顺序

1. 当前仅完成项目记忆，真实状态与差距见 [06](06_CURRENT_STATE.md)。百关几何已设计并获认可，不重复启动几何逐关等待。
2. 明确新 UI 生产路线、视觉基线、工具职责与验收门禁；不自动恢复旧整屏转绘流程。
3. 获准后从统一组件、素材和代表页面验证新路线，再覆盖全部页面、状态与 100 关视觉；几何来自 `design/track-review/catalog.source.json`。
4. Cocos 试样与正式重构分别取得明确任务授权，按 [下一任务](07_NEXT_TASKS.md) 推进，不借设计任务扩张代码变更。
5. 在正式游戏交付前完成旧代码规则差距修复、百关接入、生成计划、首撞/动态回吸/可解性验证。几何通过不替代这些工作。
6. 最终完成平台能力、真机 QA、性能与包体、审核资料和灰度调优；当前未达上线状态。

## 13. 第一阶段禁止项

首发不得加入：复杂公寓装修、喂食成长、繁殖、抽卡、PvP、组队、公会、聊天、好友拜访、关卡编辑器、内购、用户图片上传、实时 AI 生成或大型运营后台。

## 14. 第二阶段：生成“我家的猫”

### 14.1 阶段 A：参数化捏猫

先提供不上传照片的捏猫：脸型、毛色、花纹、眼睛、耳朵、尾巴和昵称。昵称必须经过文本安全检测。系统通过统一素材层组合出专属猫咪和多种游戏表情。

### 14.2 阶段 B：照片生成

抖音小游戏当前虽然提供相册选图接口，但平台内容规范对用户自定义图片上传存在明确限制。只有取得平台对具体方案的书面确认后，才允许进入开发。

获准后的建议流程：用户同意隐私说明 → 本地裁剪猫主体 → 压缩并移除元数据 → 内容安全检查 → 拒绝人物/人脸或非猫图片 → 提取毛色与花纹等特征 → 映射为统一分层素材 → 生成多表情贴图 → 默认仅本人可见 → 删除原始照片并提供结果删除能力。

优先采用“AI 特征提取 + 分层素材组合”，不采用每局实时生成整张猫图，以保证成本、速度、画风和动画一致性。

### 14.3 进入第二阶段的条件

- 次日留存达到约 20%～25%。
- 首次会话中位时长超过 6 分钟。
- 呼噜暴走高光确实能带来分享。
- 玩家对“自定义我家猫”表现出明确需求。
- 第一阶段运营成本可控。
- 平台对图片处理方案给出明确、可执行的意见。
